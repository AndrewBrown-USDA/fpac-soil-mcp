# AGENTS.md - FPAC Soil MCP Server

## Quick Start

```powershell
# Install locked runtime and development dependencies
uv sync

# Run the MCP server over stdio (default)
uv run fpac-soil-mcp

# Run the mocked test suite
uv run pytest -m "not live_sda"

# Run one test file
uv run pytest tests\test_sda_client.py

# Lint and check formatting
uv run ruff check .
uv run ruff format --check .

# Build and run the container
docker build -t fpac-soil-mcp .
docker run -i --rm -e MCP_TRANSPORT=stdio fpac-soil-mcp
```

Live SDA tests require network access:

```powershell
uv run pytest -m live_sda
```

## Find Things

- `main.py` - console-script entry point selected by `[project.scripts]` in `pyproject.toml`.
- `src\fpac_soil_mcp\app.py` - FastMCP factory; wires tools, resources, prompts, and custom routes.
- `src\fpac_soil_mcp\config.py` - environment and `.env` settings.
- `src\fpac_soil_mcp\sda_client.py` - USDA SDA HTTP client, validation, fixed SQL templates, retries, and response parsing.
- `src\fpac_soil_mcp\models.py` - Pydantic response schemas.
- `src\fpac_soil_mcp\constants.py` - regulatory notices, limitations, citations, and farmland class definitions.
- `src\fpac_soil_mcp\tools\` - MCP tool implementations and registration.
- `src\fpac_soil_mcp\resources\` - MCP resource implementations and registration.
- `src\fpac_soil_mcp\prompts\` - MCP prompt implementations and registration.
- `src\fpac_soil_mcp\routes.py` - HTTP-only `/health` and `/meta` routes.
- `tests\` - pytest coverage for the client, server registration, and tools; shared mocks live in `tests\conftest.py`.
- `pyproject.toml` - package metadata, dependencies, script entry point, pytest markers, and Ruff settings.
- `.env.example` - supported environment variables and defaults.
- `Dockerfile` - production container build.
- `server.json` and `manifest.yaml` - MCP registry and capability metadata.
- `README.md` and `QUICKSTART.md` - user-facing setup, client configuration, API behavior, and regulatory scope.
- `planning\` - planning artifacts; inspect the directory rather than treating task-state files as project truth.

## Workflows

### Add or Change an MCP Tool

1. Implement the domain or SDA behavior in the appropriate module under `src\fpac_soil_mcp\`.
2. Define or update response types in `models.py`.
3. Add the callable and its `mcp.tool(...)` registration under `tools\`.
4. Export and register it through `tools\__init__.py`; `app.create_mcp_server()` consumes the package registrar.
5. Add mocked tests under `tests\`; add a `live_sda` test only when the behavior requires the real service.
6. Update `README.md`, `manifest.yaml`, and `server.json` when the public MCP surface changes.

### Add or Change Resources, Prompts, or HTTP Routes

- Resources: implement under `resources\`, then wire through `resources\__init__.py`.
- Prompts: implement under `prompts\`, then wire through `prompts\__init__.py`.
- Routes: register them in `routes.py`; verify them with a network transport, not stdio.
- Keep all component registration centralized in `app.create_mcp_server()`.

### Validate a Change

```powershell
uv run pytest -m "not live_sda"
uv run ruff check .
uv run ruff format --check .
```

Run `uv run pytest -m live_sda` separately when changing requests, SQL templates, parsing, retries, or live integration behavior.

## Infrastructure

- Python: `>=3.11`; package and environment management use `uv` with `uv.lock`.
- Default transport: `stdio`.
- Network transports: set `MCP_TRANSPORT=sse` or `MCP_TRANSPORT=http`; default bind is `127.0.0.1:8000`.
- Configuration loads from environment variables and an optional repository-root `.env`; copy `.env.example` for local overrides.
- Upstream service: USDA NRCS Soil Data Access Tabular API, configured by `SDA_TABULAR_URL`.
- HTTP routes: `/health` and `/meta` are registered on the FastMCP application for network transports.
- Tests use mocked `httpx` transports by default. Tests marked `live_sda` contact the external USDA service and are opt-in.
- SDA responses use `JSON+COLUMNNAME`, where the first table row contains column names; parsing is centralized in `SDAClient`.

### Operational Rules

- Preserve the preliminary-screening limitation in every soil-query response: this service does not produce an official FPPA determination, LESA score, Form AD-1006, or NRCS-CPA-106.
- Keep regulatory language and citations centralized in `constants.py`; do not duplicate divergent notices in tools.
- Accept only validated coordinates or numeric positive `mukey` values. Do not add user-supplied SQL passthrough.
- Keep SDA queries in fixed templates and retain explicit errors, retry behavior, source metadata, and coverage status.
- Do not make live SDA tests part of the default offline test path.
- Do not commit `.env`, credentials, local virtual environments, caches, or generated bytecode.
