### Confirmed diagnostic defect and correction

For the three adversarial cases, `_structured_status` selected `running` from
transient `partialResult.details.calls[].status` fields and reported that as the
case-level status. The same event streams also contain terminal MCP call statuses
(`ok` and, in one call, `error`); these describe invocations, not the case's
expected FPPA status. The runner's `max_tool_calls` semantic diagnostic is also
an event-derived tally across structured event snapshots, not a verified count
of unique logical invocations.

Updated `_structured_status` to ignore statuses nested in `calls` and
`nestedCalls`, and added a regression test for the captured progress/terminal
event shape. The live cases were not rerun: the deterministic regression test
directly covers the parser defect, and rerunning model cases would not establish
an application behavior change.
