# 40.2.1 AOI handoff evidence

## Result

**AOI integration is blocked.** The current decorated MLflow Agent Server
handlers do not prove that `custom_inputs` are redacted before automatic trace
capture. `mlflow.openai.autolog()` is configured at module import, while
`invoke_handler` and `stream_handler` receive the already-parsed
`ResponsesAgentRequest`; handler-level filtering can keep geometry out of
model messages, but cannot establish pre-trace exclusion.

## Request path

The vendored frontend uses the template's `/api/chat` AI SDK transport. Its
request body contains chat messages and template fields; no `custom_inputs`
or AOI-specific request field is currently sent. The frontend therefore does
not yet provide a production custom-input round trip.

The backend handlers currently pass only normalized `request.input` to
`Runner.run`/`Runner.run_streamed`. `custom_inputs` are not model context.
`sanitize_custom_inputs` retains only an opaque `session_id` for trace
correlation and rejects geometry, WKT/GeoJSON, bounding boxes, and parcel
properties. This is a defense-in-depth history/model boundary, not proof of
pre-trace redaction.

## Output path

No evidence was found that the vendored AI SDK adapter preserves a
non-model `custom_outputs.map_layers` field through `/api/chat`. The current
frontend consumes AI SDK stream data and does not expose a custom-output
integration hook. The M3 authoritative `map` envelope is not implemented.

## Privacy decision

Raw AOIs must remain browser/session-only and must not be copied into prompts,
ordinary chat history, traces, or persistent storage. Only opaque identifiers
and bounded metadata may be used for telemetry after a platform-level
pre-dispatch boundary is demonstrated. A handler sanitizer alone is
insufficient, so AOI dispatch remains blocked pending an instrumented
pre-trace probe or supported platform redaction hook.
