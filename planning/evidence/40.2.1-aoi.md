# 40.2.1 AOI handoff evidence

## Result

**AOI integration is blocked.** The current decorated MLflow Agent Server
handlers do not prove that `custom_inputs` are redacted before automatic trace
capture. `mlflow.openai.autolog()` is configured at module import, while
`invoke_handler` and `stream_handler` receive the already-parsed
`ResponsesAgentRequest`; handler-level filtering can keep geometry out of
model messages, but cannot establish pre-trace exclusion.

## Request path

The vendored frontend uses the template's `/api/chat` chat SDK transport. Its
request body contains chat messages and template fields; no `custom_inputs`
or AOI-specific request field is currently sent. The frontend therefore does
not yet provide a production custom-input round trip.

The backend handlers currently pass only normalized `request.input` to
`Runner.run`/`Runner.run_streamed`. `custom_inputs` are not model context.
The MLflow trace session comes from `get_session_id`, which uses
`context.conversation_id` first and falls back to `custom_inputs.session_id`.
(Correction, Plan 41 task 41.1.1: an interim `sanitize_custom_inputs` filter
was removed. It dropped `context.conversation_id`, which is the field the
vendored UI actually sends, and it did not prove pre-trace redaction.)

Exact adapter loss (Plan 41 research, upstream `databricks/app-templates`
commit `0e57297`, see `planning/RESEARCH_AGENT_APP_FRONTEND_VENDORING_FIXES.md`):
the template's server, packages, and client source contain no `custom_inputs`
or `custom_outputs` handling at all. The server forwards only messages plus
`context.conversation_id` and `context.user_id` to `/invocations`. A
`custom_inputs` AOI field therefore cannot reach the handler through the chat
transport without new template code.

## Output path

The upstream template (commit `0e57297`) has no `custom_outputs` handling, so a
non-model `custom_outputs.map_layers` field is not forwarded through
`/api/chat` to the browser. The frontend consumes chat SDK stream data only and
exposes no custom-output integration hook. The M3 authoritative `map` envelope
is not implemented.

## Privacy decision

Raw AOIs must remain browser/session-only and must not be copied into prompts,
ordinary chat history, traces, or persistent storage. Only opaque identifiers
and bounded metadata may be used for telemetry after a platform-level
pre-dispatch boundary is demonstrated. A handler sanitizer alone is
insufficient, so AOI dispatch remains blocked pending an instrumented
pre-trace probe or supported platform redaction hook.
