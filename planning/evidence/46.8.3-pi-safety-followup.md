# Plan 46.8.3 — Pi and Databricks safety-evaluation follow-up

## Diagnosis

The shared FPPA safety policy had not been delivered consistently to the agent
evaluation surfaces. Pi also passed its multiline system prompt through a
Windows command shim; the initial post-change invocations exited with only a
session event. Passing the policy through a temporary sandbox file restored
complete structured event streams. This is consistent with a command-argument
transport issue, but the captured evidence does not independently prove the
shim's parsing behavior.

After agent output returned, `ADV-INJECTION-01` invoked a scope tool despite a
zero-call budget. The Pi wrapper unconditionally required tool/prompt use, and
the Databricks runner used forced tool use by default while omitting per-case
tool-use and budget settings from agent inputs. The shared case adapter and
both runners now honor zero-call cases without forcing an MCP call or prompt
render.

The first reruns after the zero-call change made no structured tool calls but
still failed exact keyword and required-behavior checks. Locally inspecting
captured structured events showed equivalent refusal/privacy/boundary language
that the deterministic matchers did not recognize. The matcher now normalizes
curly-apostrophe `can't` for keyword comparison and accepts scoped refusal
paraphrases while preserving boundary and non-echo requirements.
