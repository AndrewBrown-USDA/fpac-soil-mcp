# Task 26.2.1 Micro-plan: Propagate selector validation through tools

## Analysis

- `lesa._normalize_productivity_index` is the shared normalization seam used by
  the tool layer, but polygon analysis currently duplicates selector mapping and
  still permits legacy CSR2/CPI/Storie enum values to reach retrieval.
- Corridor analysis has its own alias normalization and only rejects `custom`;
  unsupported fixed aliases therefore can proceed to `get_productivity_ratings`.
- `soil_tools.py` normalizes in some entry points but conditionally forwards the
  original selector, so polygon, corridor, and LESA paths are not yet uniformly
  validated before analyzer/SDA work.
- The implementation must preserve NCCPI requests, existing partial-coverage
  aggregation, and LE-unavailable/indeterminate behavior established by task
  26.1.1; no statutory threshold or regulatory text changes are needed.

## Micro-plan

1. Confirm the final fixed-selector validator contract and exception behavior
   from the completed 26.1.1 changes before editing callers.
2. Replace polygon-local selector branching with the shared validator and make
   rejected CSR2/CPI/Storie values fail before geometry-dependent SDA retrieval.
3. Route corridor normalization through the same validator while preserving its
   NCCPI interpretation query and partial-coverage rating handling.
4. Update the polygon, corridor, and preliminary LESA tool wrappers to validate
   once at their public boundary and pass the normalized supported selector.
5. Ensure LESA site and corridor dispatches do not reconstruct unsupported
   selectors or accidentally bypass validation through conditional kwargs.
6. Preserve existing behavior for NCCPI, valid zero ratings, missing ratings,
   and partial coverage; do not alter threshold constants or determination text.
7. Review all three entry-point families for consistent pre-SDA rejection and
   remove only now-dead selector forwarding branches within scope.
8. Run the targeted polygon, corridor, and tool tests requested by the task.
9. Run focused lint/format checks on the three edited Python modules.
10. Record implementation and validation results for approval handoff without
    editing files outside the declared scope.

## Execution report

- Implemented shared `_normalize_productivity_index` validation at polygon and
  corridor analyzer boundaries and all three soil-tool entry points.
- Unsupported CSR2, CPI, Storie, and custom selectors now fail before geometry
  parsing or SDA access; NCCPI remains the only fixed selector.
- Focused Ruff lint passed for all changed Python modules.
- Targeted tests: **49 passed, 33 failed**. The failures are existing
  expectations for the now-removed generic CSR2/CPI/Storie/custom retrieval
  paths, plus corridor fixtures that depend on those selectors. These are
  intentional dependent-task 26.3.1 updates, not implementation regressions.
