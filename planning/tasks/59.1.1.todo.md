# 59.1.1 -- Map models and builder split

## Goal
Split the map contract so `MapBlock`/`MapLayer` hold only layer descriptors, and display geometry rides a private `MapDisplay` on the block for `_meta` (D3, D4, D10, D11).

## Notes
- `_validate_map_block` today returns `handler(value.model_dump())` for a `MapBlock` instance, which drops private attrs (hazard). Fix keeps the re-dump (stays robust across class identity) and re-attaches `_display`.
- Callers outside scope keep working at runtime: polygon/corridor analyzers and `soil_lookup_tools._soil_map_fields` only append `build_layer(...)` results to a list and pass it to `build_map_block`; soil tool then calls `block.model_dump()` (descriptor-only dump, fine until 59.1.3).
- `corridor_analyzer.py` ~1351 `footprint(...) -> MapLayer` annotation becomes stale (now `LayerBuild`); not in scope here -> Discovered for 59.1.6 (its docstring-only scope may need to include that annotation).
- `bounds_of` signature changes from `Iterable[MapLayer]` to `MapDisplay`; only caller is `enforce_size_cap` (git grep of src + app agent_server).
- Suite outside `test_map_contract.py` is expected red until 59.1.7 (D12).
- No legend, category, simplification or SDA-row code changes.
