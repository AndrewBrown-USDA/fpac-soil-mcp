# 44.7.1 -- "Show on map" on tool cards

## Goal

A completed `analyze_farmland_by_polygon` or `analyze_corridor_fppa` tool card can put its map layers on the map panel.

## Findings (read before planning)

- Agent tool calls render in the generic `Tool` branch of `ToolPartRenderer` (`message.tsx` ~L447); `toolName` is the bare MCP tool name (log shows `get_farmland_classification_by_point`), `input` is the parsed arguments, `state` / `errorText` give completion.
- Arguments for an AOI call carry the reference string (`"geojson": "aoi-xxxxxxxx"`); the agent substitutes it server-side, so the card has no geometry. `/api/geo/map` substitutes only when `active_aoi.aoi_ref` matches.
- `ChatLayout` owns `mapOpen`; `ActiveAoiProvider` wraps both the map panel and the chat `Outlet`, so a sibling provider reaches the tool cards and the panel.
- `MapPanel` draws `screening.result.display.map` with `renderMapBlock`; `ScreeningResults` shows notice, legend, table.

## Decisions

- One "shown result" slot in `MapResultContext`: `{ origin: 'screening' | 'tool', tool?, block, regulatory_notice, authority?, toolCallId? }`. A finished screening and a "Show on map" click both set it; the last action wins. Provider takes `onShow` so `ChatLayout` opens the panel.
- Below the map: a screening result keeps `ScreeningResults`; a tool result shows "Map of <tool> result", its notice verbatim, `MapLegend`, and "Back to screening" when a screening result exists.
- The slot clears on chat switch and when the AOI changes or is cleared.
- Card button states: idle, loading, shown, error (fixed text per status: 400 "cannot be shown", 413 "too large", 502 "map service unavailable"), not available (AOI reference in the arguments is not the active AOI, or the tool errored). Nothing from the arguments is logged.
- Fit bounds to `block.bounds` when present, else the AOI.
