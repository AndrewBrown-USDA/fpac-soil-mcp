# 7.3.1 — Multi-County Corridor Analysis & Reconciliation Engine

## Goal
Implement `CorridorAnalyzer` in `src/fpac_soil_mcp/corridor_analysis.py` and response models in `src/fpac_soil_mcp/models.py` to ingest corridor centerlines, buffer distances/units, optional indirect staging footprints, and alternative alignments, partition the footprints across county boundaries via TIGERweb, query SSURGO soils via SDA spatial intersection per county segment, integrate NASS agricultural baselines, calculate composite relative Land Evaluation ratings ($RR_{\text{composite}}$), and enforce sum reconciliation within 0.1% tolerance, verified in `tests/test_corridor_analysis.py`.

## TODO Items
- [x] 1. Update `src/fpac_soil_mcp/models.py`:
  - Add `CorridorImpactBreakdown`: direct acres, indirect acres, total acres, and percentages.
  - Add `CorridorCountySegment`: county name, state FIPS, county FIPS, direct acres, indirect acres, total segment acres, farmland category breakdown, soil map units, NASS agricultural profile, urban screening, relative rating, and segment weight.
  - Add `CorridorAlternativeComparison`: alternative ID/name, centerline hash, total acres, direct acres, indirect acres, FPPA subject acres, composite relative rating ($RR_{\text{composite}}$), and counties traversed.
  - Add `CorridorFarmlandAnalysisResponse`: primary corridor analysis, county segments list, reconciliation summary (sum of segment acres vs total buffered acres), alternative comparisons, CSV tables, manifest, source metadata, limitations, and regulatory notice.
- [x] 2. Implement `src/fpac_soil_mcp/corridor_analysis.py`:
  - `CorridorAnalyzer` class accepting `sda_client`, `tigerweb_client`, `nass_client`.
  - Ingest centerline WKT/GeoJSON + buffer distance & unit -> generate direct polygon via `buffer_centerline`.
  - Ingest optional indirect footprint -> cleanly isolate non-overlapping indirect polygon via `erase_geometries`.
  - Total project footprint = direct polygon union indirect polygon.
  - Partition footprint across intersecting counties using `tigerweb_client.get_intersecting_counties` and `partition_geometry_by_counties`.
  - For each county segment $S_k$:
    - Perform SDA soil query using `sda_client.get_spatial_intersection(segment_wkt)`.
    - Compute FarmlandCategoryBreakdown and map unit acreages normalized to segment total acreage.
    - Fetch NASS `CountyAgProfile` via `nass_client.get_county_ag_profile`.
    - Compute Segment Relative Rating $RR_k = \sum (A_{k,i} \cdot \text{LE}_{k,i}) / A_k$ if LE available.
  - Calculate Composite Corridor Relative Rating: $RR_{\text{composite}} = \sum (A_k \cdot RR_k) / A_{\text{total}}$.
  - Reconcile sum of segment acreages against total buffered footprint; verify reconciliation variance <= 0.1%.
  - Process any alternative corridors (Alternatives B, C, D) using the same pipeline for side-by-side comparison.
  - Generate tabular CSV summary with county segment breakdowns.
- [x] 3. Implement `tests/test_corridor_analysis.py`:
  - Test single-county corridor analysis.
  - Test multi-county corridor analysis (2-county and 3-county fixtures) with mocked SDA, TIGERweb, and NASS.
  - Test indirect impact staging area integration with `erase_geometries` topological deduplication.
  - Test alternative alignment comparison (Primary vs Alternative B).
  - Test sum reconciliation enforcement (sum of county segments equals total corridor acreage within tolerance).
  - Test graceful fallback when NASS or TIGERweb returns errors or empty data.
