# Plan 54 Task 54.6.1 — Per-chat corridor context transport

## Goal
Transport validated active-corridor context independently of active AOI from each chat session into the agent request's `custom_inputs.active_corridor`, with focused coverage and a complete ADR 0015 vendored-path ledger.

## Micro-plan
- [ ] Add corridor session model/storage helpers in `frontend/client/src/components/map/corridorSession.ts`, using a separate chat-keyed `sessionStorage` entry and set/detach/state APIs; safely drop malformed persisted values.
- [ ] Test per-chat save/restore, chat switching, detach, malformed values, and independence from AOI in `corridorSession.test.ts`.
- [ ] Add `ActiveCorridorContext.tsx` provider/hooks exposing chat state plus set, detach, and state APIs for MapPanel callers.
- [ ] Wrap `ChatLayout.tsx` in the corridor provider alongside the unchanged active-AOI provider.
- [ ] Update `chat.tsx` to send the active chat's corridor context with each turn while preserving `activeAoi` and permitting both contexts together.
- [ ] Extend `schemas/chat.ts` with bounded optional corridor validation at the existing request boundary; malformed corridor input is dropped without changing active-AOI behavior.
- [ ] Extend `providers-server.ts` with a request-scoped corridor registry/key and injection into `custom_inputs.active_corridor`, preserving existing custom inputs and active AOI.
- [ ] Update `server/src/routes/chat.ts` to register corridor context per request, pass only its opaque key, and release it on request close.
- [ ] Update ADR 0015's local-changes ledger for every modified vendored file and each added frontend path.
- [ ] Run from `apps/agent-fpac-soil-openai-sdk/frontend`: `node --import tsx --test client/src/components/map/corridorSession.test.ts` and `npm run test:site-assessment`; inspect diff and ledger completeness.
