# Plan 43.2.1 — Integrate Criterion 2 into unified LESA paths

## Goal

Thread the accepted TIGERweb perimeter evidence through site and corridor
LESA workflows so Criterion 2 awards verified points, preserves explicit
overrides, exposes provenance and verification, and distinguishes unavailable
evidence from measured zero without changing LE calculations or authority
boundaries.

## Steps

1. [x] Reconcile the 43.1.1 model fields and 43.1.2 evidence result shape with the
   current `SiteAssessmentCriterion`, `SiteAssessmentSummary`, and analysis
   response models; preserve the mandatory preliminary regulatory notice.
2. [x] Trace the existing `PolygonAnalyzer.analyze_polygon` and
   `CorridorAnalyzer.analyze_corridor` geometry/TIGERweb seams and identify the
   precise perimeter geometry and client calls that can supply Criterion 2
   evidence without duplicating requests or changing county partitioning.
3. [x] Add a shared LESA Criterion 2 input/evidence path in `lesa.py` that accepts
   measured evidence, preserves explicit user criterion overrides, maps the
   normalized ratio through the accepted rule, and records rule, provenance,
   evidence status, and verification fields.
4. [x] Ensure unavailable, upstream-error, invalid, and measured-zero evidence remain
   distinct; unavailable evidence must not be silently converted into measured
   zero or implied agricultural adjacency.
5. [x] Preserve site and corridor evaluator limits and total-score behavior,
   including corridor statutorily zeroed criteria and the 160-point threshold;
   do not alter LE normalization or unrelated criteria.
6. [x] Thread site/AOI perimeter evidence from `PolygonAnalyzer` into the unified
   LESA inputs and response path, retaining existing invalid-geometry,
   SDA-error, and response limitation behavior.
7. [x] Thread corridor perimeter evidence from `CorridorAnalyzer` through the
   corridor LESA orchestration, preserving dynamic TIGERweb county partitioning,
   segment reconciliation, alternatives, and corridor-specific scoring limits.
8. [x] Update only the relevant tool wiring (`lesa_tools.py` and/or
   `spatial_analysis_tools.py`) so `calculate_preliminary_lesa`,
   `analyze_farmland_by_polygon`, and `analyze_corridor_fppa` expose the
   integrated Criterion 2 fields without changing public arguments
   unnecessarily.
9. [x] Add focused LESA tests for measured site and corridor mappings, unavailable
   evidence, measured zero, explicit Criterion 2 overrides, provenance/rule/
   verification fields, corridor limits, and threshold behavior.
10. [x] Add focused polygon and corridor integration tests using mocked TIGERweb
    evidence to verify evidence propagation, unavailable-vs-zero behavior, and
    preservation of existing analysis outputs and preliminary notices.
11. [x] Run exact targeted validation:
    `uv run pytest tests\test_lesa.py tests\test_polygon_analysis.py tests\test_corridor_analysis.py -q`
    and, if tool wiring changes require it,
    `uv run pytest tests\test_phase2_contracts.py tests\test_phase3_contracts.py -q`.
12. [x] Run targeted Ruff and formatting checks on all changed in-scope source and
    test files; record results and any explicit external limitations in this
    task record.

## Notes

- ADR 0003 requires every screening response to remain explicitly preliminary;
  no official FPPA determination, agency-approved LESA score, AD-1006, or
  CPA-106 may be implied.
- ADR 0006 requires reuse of dynamic TIGERweb behavior for corridor workflows;
  do not add a bundled boundary source or collapse multi-county evidence.
- ADR 0007 keeps shared LESA scoring in `lesa.py` while preserving the existing
  corridor orchestration and project-type-specific limits.
- Wave 1 reports establish Criterion 2 as a bounded ratio with measured,
  unavailable/error evidence states, rule/version, provenance, and verification
  fields; use those exact accepted names and semantics.
- Keep live-network tests out of this task unless an existing integration seam
  cannot be validated with mocks; live coverage belongs to 43.3.1.

## Questions

- None blocking for micro-planning. During implementation, confirm whether
  corridor Criterion 2 evidence is aggregated once for the buffered corridor
  or composed from county segments; follow the existing 43.1.2 helper contract
  and preserve a single transparent provenance record.
