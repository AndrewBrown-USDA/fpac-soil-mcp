# Task 26.1.1 Micro-plan: Align selectors and unavailable LE semantics

## Analysis

- `ProductivityIndexType` currently exposes `NCCPI`, `CSR2`, `CPI`, `STORIE`, and
  `CUSTOM` in `models.py`; `integration_models.py` contains only provenance-bearing
  SDA records and has no selector enum. The corrected scope includes `models.py`,
  so the public enum can be aligned directly with the reliable selector contract.
- `SDAClient.get_productivity_ratings()` and
  `get_county_max_productivity_rating()` currently issue broad fixed `LIKE` queries
  for CSR2/CPI/Storie and dynamically look up arbitrary selector text when no fixed
  branch matches.
- The explicit `attribute_meta` paths already call metadata-validated dynamic query
  builders and must remain available as the future internal seam.
- `evaluate_land_evaluation()` currently returns `candidate_le_score=0.0` and
  `aoi_relative_rating=0.0` when `rated_acres == 0`; this must become unavailable
  semantics without confusing a valid rated zero with no rated coverage.
- `evaluate_corridor_lesa()` already maps `land_evaluation_score is None` to
  `total_lesa_score=None` and `threshold_exceeded=None`; the change should preserve
  and reuse that path. `corridor_scoring.py` is the reference implementation for
  corridor unavailable behavior.
- `integration_models.py` appears to need no behavioral change unless analysis of
  the final selector/provenance contract identifies a directly related schema
  adjustment; no unsupported public metadata/documentation should be added.

## Micro-plan (implementation after orchestrator approval)

1. Update `ProductivityIndexType` in `models.py` to retain deterministic national
   NCCPI support and remove unsupported public CSR2/CPI/Storie options, preserving
   `CUSTOM` only where required for internal normalization/error compatibility.
2. Reconcile the fixed selector contract with the live catalog, retaining only the
   deterministic national NCCPI selector for fixed SDA retrieval and rejecting
   unsupported generic selector aliases before SDA queries.
3. Remove or bypass the fixed CSR2/CPI/Storie query branches and generic
   `lookup_sdv_attribute(index_type)` fallback in both productivity retrieval and
   county-maximum retrieval, while preserving explicit `attribute_meta` handling.
4. Keep `lookup_sdv_attribute()` and both `build_dynamic_sdv_query` seams
   metadata-validated and injection-safe; do not add a public `sdvattribute`
   parameter or alter unrelated query behavior.
5. Adjust LE aggregation so zero rated acreage produces unavailable/indeterminate
   output suitable for the existing LE-unavailable threshold path, while a rated
   map unit whose normalized rating is legitimately `0.0` remains scoreable.
6. Thread the unavailable LE result through `evaluate_lesa`/threshold helpers as
   needed, preserving existing notices, provenance, and response schemas.
7. Verify corridor scoring continues to return `total_lesa_score=None` and
   `threshold_exceeded=None` for unavailable LE, with no false below-threshold
   determination; make only tightly coupled changes in `corridor_scoring.py`.
8. Audit the named `integration_models.py` surface for any required status or
   numeric-rating compatibility adjustment, leaving it unchanged if no selector
   contract is defined there.
9. Run the targeted regression command below and inspect failures only within the
   five in-scope source files; do not modify tests or other production modules in
   this task.
