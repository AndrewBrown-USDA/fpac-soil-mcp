# 40.2.1 -- Prove request/output and privacy boundaries
## Goal
Prove the vendored chat frontend and agent handlers can carry non-model request/output metadata without allowing raw AOI geometry into model context, traces, or ordinary history, using explicit backend pre-dispatch and session-only AOIs.
## TODO items
- [ ] Inspect the vendored frontend's request construction and response/stream adapter to determine how `custom_inputs` are sent and whether `custom_outputs.map_layers` (or an equivalent non-model field) survives; add the smallest focused frontend/template probe or document the exact adapter loss.
- [ ] Trace the `ResponsesAgentRequest` capture order around `invoke_handler`, `stream_handler`, MLflow autologging, MCP dispatch, and history normalization; define a sanitized metadata shape limited to opaque identifiers/metadata and exclude coordinates, WKT/GeoJSON, bounding boxes, and parcel properties.
- [ ] Implement the minimum safe backend pre-dispatch boundary in `agent.py`/`history.py` needed by the evidence, without adding wrapper MCP tools, durable AOI persistence, or the M3 authoritative `map` envelope; keep raw AOIs session-only and outside prompts, ordinary history, traces, and persistent storage.
- [ ] Add focused offline coverage in `tests\test_aoi_handoff.py` for custom-input handling, sanitized model/history inputs, custom-output preservation or explicit loss, and both invoke/stream paths as applicable.
- [ ] Write `planning\evidence\40.2.1-aoi.md` with the probe results, capture-order evidence, redaction/exclusion evidence, and any platform-limited unknowns; do not convert an unproven pre-trace guarantee into success.
- [ ] Write `planning\decisions\40.2.1-aoi.md` recording the accepted explicit backend pre-dispatch path, opaque telemetry identifiers, session-only AOI lifecycle, preliminary-screening and separate-MCP-client boundaries, and pass/fail blockers for future AOI integration.
- [ ] Run the targeted acceptance command `cd apps\agent-fpac-soil-openai-sdk && uv run --frozen --python 3.11 pytest tests\test_aoi_handoff.py -q`; report exact results and stop if the same failure occurs twice for the same reason.
## Notes
The task depends on completed 40.1.1 vendoring and the repo-owned frontend is present. Current handlers pass only normalized `request.input` to `Runner` and initialize `mlflow.openai.autolog()` at module import, so the execution must establish whether sanitization happens before any automatic trace capture rather than relying on handler-level cleanup. ADR 0012 keeps the app as a separate MCP client using deployed MCP tools only; ADR 0003 preserves preliminary screening authority limits. Do not touch MCP server tools, `privacy.py`, deployment resources, frontend components, or implement M3 map envelopes. Never place raw AOI geometry in prompts, traces, ordinary history, or persistent storage.
