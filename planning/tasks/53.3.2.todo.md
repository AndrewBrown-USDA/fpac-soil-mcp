# Task 53.3.2 — Persist raster order while pinning vectors above rasters

## Goal
Let users arrange optional raster/context overlays with accessible controls and browser-local persistence, while ensuring every result vector and the AOI boundary stays above all rasters.

## Tasks
- [x] Inspect the current catalog, overlay insertion/removal, control props, and 53.3.1 NAIP changes in `overlays.ts`, `OverlayControl.tsx`, `overlays.test.ts`, and MapPanel's overlay/result/AOI layer lifecycle.
- [x] Define a stable default raster order from the overlay catalog and a pure normalization/restore helper that filters unknown or duplicate IDs and handles missing, malformed, and catalog-changed storage.
- [x] Add pure helper tests for default order, valid persisted order, malformed storage, duplicate/unknown IDs, and catalog additions/removals.
- [x] Add local-storage persistence and accessible reorder controls for optional layers in `OverlayControl.tsx`; preserve toggle status and never permit non-catalog IDs.
- [x] Add an overlay stack operation that applies the selected raster order to actual MapLibre layer order while placing the raster stack below the first result vector layer and AOI boundary.
- [x] Integrate ordering with overlay enable/disable and map style/layer lifecycle without changing server result styling or map contracts.
- [x] Add MapLibre-level focused tests (or extend a suitable existing seam) proving reordering affects raster order and every result vector plus AOI remains above CDL/NAIP, including overlays added after vectors.
- [x] Update `docs/decisions/0015-vendored-agent-app-frontend.md` `### Local changes` ledger for every modified or added vendored frontend path in the same implementation change.
- [x] Run from `apps/agent-fpac-soil-openai-sdk/frontend`: `node --import tsx --test client/src/components/map/overlays.test.ts` (and any new focused ordering test file), `npm run build`, and `git diff --check`.
- [x] After targeted checks pass, create a focused local Conventional Commit; report the commit ID, exact results, and any limitation. Do not run shared/full suites.

## Facts and constraints
- Dependency 53.3.1 is complete (`64bea1f`); `overlays.ts` catalog includes `ssurgo`, `counties`, `urban`, `cdl`, and `naip`.
- `addOverlay` currently inserts before the first `result-*` layer, otherwise before `aoi-line`; order changes must preserve this vector-on-top boundary, including when layers are added/re-added.
- `OverlayControl.tsx` renders catalog toggles; `overlays.test.ts` already verifies fixed NAIP source metadata and source ID mapping.
- Allowed implementation files are `overlays.ts`, `OverlayControl.tsx`, focused tests, and ADR 0015. Do not edit `MapPanel.tsx`, server contracts, chat export, AOI labeling, or result vector styling.
- Keep all overlay endpoints fixed; no dependency additions. Local storage is browser-only. Use accessible control names and preserve keyboard operation.
- ADR 0015 requires every modified/added vendored frontend path in its `### Local changes` ledger in the same implementation change.

None; the task specification and existing integration seam define the required behavior.
