# Plan 43.1.2 Micro-plan

## Goal

Add a reusable TIGERweb perimeter-intersection evidence helper that returns a
bounded agricultural-adjacency ratio with explicit provenance and unavailable
states, without changing live-test defaults or unrelated clients.

## Steps

1. Confirm the helper’s public result shape against the accepted Criterion 2
   contract from task 43.1.1 and existing `IntegrationStatus`/`Provenance`
   conventions; do not duplicate regulatory notices.
2. Identify the existing TIGERweb request construction, retry/error path,
   geometry parsing, polygon-part extraction, and acreage calculation seams in
   `tigerweb_client.py` and `geometry.py`.
3. Define the perimeter evidence operation in `tigerweb_client.py`, including
   input validation, deterministic geometry hashing, source layer/version,
   method version, and explicit status/error fields.
4. Reuse `parse_geojson_geometry`, Shapely intersections, `_polygonal_parts`,
   `unary_union`, and `calculate_acreage`; do not add a new GIS dependency or
   external provider.
5. Compute a bounded ratio from the project perimeter evidence and TIGERweb
   intersected geometry, preserving zero as a measured result and distinguishing
   unavailable/error from zero overlap.
6. Handle Polygon, MultiPolygon, multipart response geometry, empty results,
   invalid response geometry, and boundary-touching intersections explicitly;
   never silently coerce failures to zero.
7. Preserve ADR 0006 dynamic TIGERweb usage, ADR 0009 shared retry composition,
   and ADR 0003 preliminary-screening authority boundaries.
8. Add focused mocked tests in `tests/test_tigerweb_client.py` for normal,
   multipart, boundary-touching, upstream-error, unavailable, invalid, and
   empty cases, including request payload assertions where appropriate.
9. Add focused geometry tests in `tests/test_geometry.py` only for any
   reusable geometry helper introduced by this task, covering empty and
   multipart behavior.
10. Add or extend the opt-in live TIGERweb test anchor in
    `tests/test_live_tigerweb.py` only if the helper requires a live contract;
    keep `pytest.mark.live_network` and skip/error handling intact.
11. Run exact targeted validation:
    `uv run pytest tests/test_tigerweb_client.py tests/test_geometry.py`
    and, if live coverage is added, `uv run pytest -m live_network tests/test_live_tigerweb.py`.
12. Run `uv run ruff check src/fpac_soil_mcp/tigerweb_client.py
    src/fpac_soil_mcp/geometry.py tests/test_tigerweb_client.py
    tests/test_geometry.py` and `uv run ruff format --check` on the same files;
    record outcomes in the implementation task record.

- TIGERweb remains the sole external evidence source.
- Network failures must remain explicit and must not become an apparent
  no-adjacency result.
- Preserve existing `check_urban_exemption` and county partition behavior.
- Do not touch SDA SQL, NASS behavior, arbitrary SQL/HTTP passthrough, LESA
  integration, public metadata, or live-test defaults.
- This helper is preliminary evidence only; it must not claim an official FPPA
  determination, agency-approved score, or Site Assessment.
