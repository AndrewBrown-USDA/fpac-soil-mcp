# 44.6.1 -- Generic map layer renderer

## Goal

The map panel draws the server `map` block (ADR 0017) instead of the hard-coded `soil` source, with legends, notes and authority from the server.

## Findings (read before planning)

- `MapPanel.tsx` adds a fixed `soil` source (fill by `FARMLAND_FILL_COLOR`, keyed on a client `farmland_class` from `withFarmlandClass`) and an `aoi` source/line on top; status text counts `display.soil_polygons` features.
- `Legend.tsx` and `ResultsTable.tsx` use client `FARMLAND_CLASSES` (patterns only `solid` / `hatched`). The server legend differs: statewide is `diagonal_hatch`, unique `cross_hatch`, local `dot_stipple`, not prime `outline` (strategy section 5). Server legend wins.
- `/api/geo/screen` passes `display.map` but not the result `authority`; each layer carries `authority` (`user_input`, `machine_estimate`, `reference_data`).
- `farmlandClasses.ts` imports the `SoilFeatureCollection` type from `useScreening.ts`; it is not in scope, so that type stays.
- Frontend checks are biome lint + `npm run build` (tsc + vite); no frontend unit tests.
