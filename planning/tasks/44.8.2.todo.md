# 44.8.2 -- Overlay catalog and toggles

## Goal

Three switchable context layers on the map, loaded by the browser straight from the public services (D5): SSURGO map units, TIGERweb counties, TIGERweb 2020 urban areas.

## Findings (2026-11-05, server-side requests with the dev app `Origin`)

- SSURGO WMS `GetMap` `mapunitpoly` at z12/14/16: 200 PNG, 17-108 KB, 0.5-1.0 s per tile; CORS `*`.
- TIGERweb counties are scale-banded generalized layers on `State_County/MapServer`: 1 (to 1:42k), 3 (to 1:90k), 5 (to 1:325k), 7 (to 1:1.4M), 9, 11, 13. `export` with `layers=show:1` alone is blank above z14; with `layers=show:1,3,5,7,9,11,13` it draws at z7-z16 (about 1-3 KB, about 0.35 s per tile). CORS echoes the app origin.
- TIGERweb `Urban/MapServer` layer 0 `export` draws from z8 (blank at z6 in the test tile); 2-10 KB per tile.
- All three are simple GETs; no custom headers (TIGERweb preflight has no CORS header).

## Decisions

- All three overlays are raster tiles (`{bbox-epsg-3857}` templates): SSURGO WMS `GetMap`; TIGERweb `MapServer/export` images. Vector `query` stays for identify and Use as AOI (44.9.1). Light, no client geometry, service draws the outlines.
- Zoom ranges: SSURGO from z12 (polygons legible), counties from z6, urban areas from z7. Below the range the control says "Zoom in to see" for that layer.
- Catalog is one `as const` array of string constants in `overlays.ts`: id, title, URL template, min zoom, opacity, source, vintage, attribution, and the label "Context layer, not an analysis result". Nothing from user input or the chat goes into a URL; MapLibre fills only `{bbox-epsg-3857}`.
- Draw order: basemap, overlays, server result layers, AOI outline. An overlay turned on after a result is drawn goes below the first `result-` layer.
- Control: a fieldset of checkboxes (keyboard and screen reader friendly) below the map toolbar, all off by default, per-layer status: loading, shown, "Zoom in to see", or "Could not load this layer" from `map.on('error')` matched by source id. Overlay errors never set the basemap tile error.
- Overlay state lives in the panel (not stored): resets on reload.
