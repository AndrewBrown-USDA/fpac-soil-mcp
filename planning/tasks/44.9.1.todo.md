# 44.9.1 -- Identify popups and Use as AOI

## Goal

Clicking the map with a context overlay on shows what is there; a county or urban area can become the chat's AOI when its exact outline fits the vertex cap (D6).

## Findings (2026-11-05)

- TIGERweb point `query` (`returnGeometry=false`, `f=geojson`) at -93.62, 42.03: counties `{GEOID: 19169, NAME: Story County, STATE: 19, COUNTY: 169}`; urban `{GEOID: 02062, NAME: Ames, IA Urban Area, UA: 02062}`.
- SSURGO `GetFeatureInfo` `text/plain`: `areasymbol`, `spatialversion`, `musym`, `nationalmusym`, `mukey`, `muareaacres`, `mupolygonkey` as `key = 'value'` lines. No map unit name or farmland class (44.1.2).
- `geo.py` vertex rule: every ring position counts, closing position included (`len(ring)`), summed over rings and polygons; cap `GEO_MAX_VERTICES`, default 2000.
- Terra Draw handles clicks in polygon, rectangle and edit modes; identify must run only in static mode.

## Decisions

- Click in static mode with at least one overlay on and inside its zoom range: query those overlays in parallel at the click point; one MapLibre popup with a section per overlay (loading, result, "Nothing here", or "Could not load"). A new click replaces the popup.
- SSURGO section: map unit symbol, mukey, survey area, polygon acres, and the line "Farmland class and map unit name are not in this service; run screening for this area." No class lookup (no backend route in this task's scope).
- County and urban sections: name, GEOID, vintage, "Context layers, not analysis results.", and "Use as AOI".
- Use as AOI: query by `GEOID` (digits only, taken from the service response, else refused) with `returnGeometry=true`, `outSR=4326`, no `maxAllowableOffset`; parse with `toPolygonGeometry`; count with `countVertices` (port of the `geo.py` rule) against 2000. Over the cap: "This outline has N vertices; the AOI limit is 2000. Draw or paste a smaller AOI." and no change. Otherwise `replaceAoi(geometry)`, fit bounds, close the popup.
- All request URLs are built in `identify.ts` from constant bases plus click coordinates or a validated GEOID; simple GETs, no custom headers. Nothing is stored or logged.
