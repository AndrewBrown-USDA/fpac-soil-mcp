# Research report: Visual identity for the FPAC Soil agent map app

## Executive summary

The app already combines a soil-map viewer with an agent workflow: users draw, edit, or paste an area of interest (AOI), screen it, inspect map features, and show selected agent-tool results on the map. Its visual foundation is still recognizably Databricks’ chat UI: the layout uses familiar chat surfaces, mostly utility-class styling, and a standard USGS topographic basemap. **The opportunity is to add a distinctive FPAC/soil-cartography visual layer—not to replace the map, change its workflows, or reinterpret its analysis.** The safest first step is to refine the existing tokens and map-panel composition: clearer land-data hierarchy, an intentional header and map toolbar, compact but scannable result summaries, and more polished controls and feedback. Keep map symbology, legends, source/authority labeling, and screening limits consistent with the server contract. These observations refer to repository commit `8c90f0d6cf01d334fa089cafc2c371bda8e734ce`, confirmed by code search and the current checkout; repository links below are pinned to that SHA.

## Current structure and constraints

### App structure and workflows

- The app is a Databricks chat agent that calls the deployed FPAC Soil MCP server. Its frontend is a vendored chat application, with the map panel added to the chat layout; app-specific onboarding identifies `MapPanel.tsx` as the map entry point and `ChatLayout.tsx` as the map/chat composition point ([`AGENTS.md`, lines 1–3 and 25–27](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/AGENTS.md#L1-L3)).
- The layout places the map beside chat on medium and larger screens, initially open there, and behind a toggle on narrow screens. The panel occupies 40% of the desktop width when open ([`ChatLayout.tsx`, lines 14–18 and 59–80](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/layouts/ChatLayout.tsx#L14-L18)).
- Map tasks include drawing polygon/rectangle AOIs, editing, undoing or clearing them, pasting GeoJSON, identifying map locations, enabling context layers, running screening, and viewing results. Results include a regulatory notice, legend, and analysis table; the map stays at a minimum height while the panel scrolls to the results ([`MapPanel.tsx`, lines 496–616](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L496-L616)).
- AOI state is associated with a chat; `ActiveAoiChip` communicates which AOI is attached, and tool cards offer “Show on map” when a result can be mapped ([`ActiveAoiContext.tsx`, lines 1–28](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/ActiveAoiContext.tsx#L1-L28); [`ActiveAoiChip.tsx`, lines 1–30](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/ActiveAoiChip.tsx#L1-L30); [`ShowOnMapButton.tsx`, lines 1–31 and 80–115](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/ShowOnMapButton.tsx#L1-L31)).

### Constraints on a visual refresh

1. **Keep the workflows intact.** AOI creation and editing, GeoJSON input, screening, identify, layer toggles, results, and “Show on map” are functional elements, not decorative details ([`MapPanel.tsx`, lines 428–485 and 496–616](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L428-L485)).
2. **Don’t restyle server analysis as though it changed.** The server’s map block supplies result styling and legends; preserve it as the source of truth ([`mapLayers.ts`, lines 1–3](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/mapLayers.ts#L1-L3)).
3. **Keep preliminary status and source provenance visible.** The map already warns that screening is not an official determination, and the results include a regulatory notice and map-layer authority/source metadata ([`MapPanel.tsx`, lines 504–506 and 580–616](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L504-L506); [`Legend.tsx`, lines 88–120](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/Legend.tsx#L88-L120)).
4. **Map interaction needs alternatives to precision gestures.** Current controls include buttons for drawing and editing, while the map itself handles click-to-identify; visual improvements should not hide or make these controls harder to use ([`MapPanel.tsx`, lines 454–485 and 508–531](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L454-L485)).

## Prioritized visual opportunities

### 1. Create a recognizable “field intelligence” visual system

**Recommendation:** Add a compact map-panel identity—e.g. an FPAC Soil title, a short “Map workspace” label, and a small active-AOI status—using the existing color and spacing tokens. Give the panel a calm field-notes aesthetic: warm off-white surfaces, restrained soil/leaf/ink accent colors, confident typography, and consistent border/radius treatment. Keep the Databricks shell and chat product framing intact.

**Why it fits:** The current map is a function-first stack of controls and panels, while the global styles remain generic app tokens ([`MapPanel.tsx`, lines 496–531](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L496-L531); [`index.css`, lines 9–18 and 110–151](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/index.css#L9-L18)). USWDS describes tokens as curated, reusable values for color, typography, and spacing; adopt that approach to make the app’s chrome consistent, while keeping data colors distinct from brand colors ([USWDS, “Design tokens”](https://designsystem.digital.gov/design-tokens/)).

**Workflow effect:** None. Treat the identity/header as presentation-only; don’t remove the existing map toggle, AOI chip, provenance, or disclaimer.

### 2. Establish visual hierarchy around the map and its controls

**Recommendation:** Present the map as the primary canvas, with a compact toolbar grouped by task: “Draw area” (Polygon, Rectangle), “Edit area” (Edit, Undo, Clear), then “Import” (GeoJSON). Give the active mode a clear selected state and pair iconography with text. Keep the layers control anchored over the map, but make its expanded state feel like a deliberate map legend/control card.

**Why it fits:** These actions already exist in a toolbar, and the layers control is a floating, keyboard-friendly native disclosure ([`MapPanel.tsx`, lines 508–531](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L508-L531); [`OverlayControl.tsx`, lines 42–80](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/OverlayControl.tsx#L42-L80)). MapLibre’s documentation describes map-style and user-interaction controls as separable from the map canvas, supporting a gradual visual layer around the existing map ([MapLibre GL JS documentation](https://maplibre.org/maplibre-gl-js/docs/)).

**Workflow effect:** Preserve the same actions and state transitions. Do not make drawing dependent on hidden hover controls.

### 3. Make screening state and results more scannable

**Recommendation:** Visually separate the preliminary notice, screening action/status, and completed result. On completion, consider a compact summary strip (AOI acres, protected farmland, coverage/status), followed by an expandable or visually grouped class breakdown, map-unit table, and layer legend. Use badges or small labels for “Your input,” “Preliminary machine estimate,” and “Reference data,” retaining the actual source and data-vintage text.

**Why it fits:** Those figures and distinctions are already available in `analysis`, the table, and legend metadata; this is a presentation opportunity, not a new analytical computation ([`useScreening.ts`, lines 20–33](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/useScreening.ts#L20-L33); [`ResultsTable.tsx`, lines 37–71](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/ResultsTable.tsx#L37-L71); [`mapLayers.ts`, lines 37–57](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/mapLayers.ts#L37-L57)). Microsoft’s HAX guidelines recommend making assistant capability and limitations clear, showing context-relevant information, supporting correction, and scoping uncertain behavior; the visual treatment should reinforce that screening is preliminary, not official ([Microsoft HAX Design Library](https://www.microsoft.com/en-us/haxtoolkit/library/)).

**Workflow effect:** Keep the existing results and table content available; avoid hiding the regulatory notice or changing the meaning of class labels.

### 4. Use map colors intentionally, with non-color distinctions retained

**Recommendation:** Keep the existing farmland classes and their meaning, but review map fill opacity, outline strength, and palette against the USGS topo background. Use the existing patterns, labels, and short codes as redundancy; make the AOI outline visually distinct from analyzed features and context layers. Avoid applying the product’s primary accent to every map class.

**Why it fits:** Class color, pattern, and code are already centralized in a mapping, while map results use server-provided styles and legends ([`farmlandClasses.ts`, lines 1–12 and 23–81](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/farmlandClasses.ts#L1-L12); [`mapLayers.ts`, lines 37–57 and 156–207](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/mapLayers.ts#L37-L57)). Esri’s guidance distinguishes categorical ramps (for distinct types) from sequential/diverging ramps and advises considering subject and background when choosing a ramp ([ArcGIS Maps SDK, “Choosing a color ramp”](https://developers.arcgis.com/javascript/latest/visualization/best-practices/choosing-a-color-ramp/)). WCAG says not to use color alone to convey information ([WCAG 2.2, SC 1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)).

**Workflow effect:** No changes to class attribution or backend symbology. Any change to server-provided colors should be handled as a separate data-contract/symbology decision.

### 5. Polish assistant-to-map handoffs without changing agent behavior

**Recommendation:** Style “Show on map” as a contextual action within each relevant tool result, and make the map panel visibly identify when it is displaying a tool result versus an AOI screening. Use clear, calm loading/success/error treatments with explicit next actions, without exposing tool arguments or inventing confidence values.

**Why it fits:** The existing handoff explicitly loads a map result from the corresponding tool card and distinguishes that origin in the map panel ([`ShowOnMapButton.tsx`, lines 80–115](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/ShowOnMapButton.tsx#L80-L115); [`MapPanel.tsx`, lines 582–616](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L582-L616)). Fluent guidance recommends using message bars for surface-level status, with distinct info/success/warning/error semantics and wrapping rather than truncating content ([Fluent 2, “Message bar — Usage”](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage)).

**Workflow effect:** Presentation only. Preserve the current chat, tool, map, and AOI relationships.

## Design-system direction and examples

A distinctive but low-risk direction is **“field atlas” / “soil survey workspace”**: federal-data clarity, natural materials, and restrained technical cartography. Concretely, this could mean a warm paper-like app surface with deep ink text and a restrained forest/soil accent; a thin survey-line motif used only in headings or map framing; and an atlas-like hierarchy in which map, AOI, analysis, and source information are visibly related without implying greater official authority. This is a recommendation, not an existing repository design decision; it should be tested with actual users before standardizing it, consistent with USWDS’s advice to start from user needs and test prototypes ([USWDS, “Design principles”](https://designsystem.digital.gov/design-principles/)).

Examples of incremental expressions of that direction:

- **Panel header:** “FPAC Soil” with a small map/field icon; a subdued “Preliminary screening” label; a compact AOI status pill tied to the active chat. The AOI reference and acres already appear in the existing chip ([`ActiveAoiChip.tsx`, lines 8–30](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/ActiveAoiChip.tsx#L8-L30)).
- **Map tools:** One consistent control style for draw/edit/import actions; selected state and focus ring are high-contrast and not color-only. Grouping and visual emphasis can change without altering the underlying functions ([`MapPanel.tsx`, lines 508–531](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L508-L531)).
- **Legend and evidence:** Keep map symbology paired with its label/code, authority, source, and vintage; use small typography hierarchy and spacing to make that information easier to scan ([`Legend.tsx`, lines 88–120](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/Legend.tsx#L88-L120)).
- **Assistant feedback:** Use the existing message/status states, but clarify them visually and make any available next action obvious; preserve full message text and the preliminary-screening caveat ([`MapPanel.tsx`, lines 543–580](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L543-L580); [Fluent 2 Message Bar](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage)).

## Risks and tradeoffs

- **Brand styling can compete with the data.** Keep brand accents in controls, framing, and typography; don’t turn the categorical soil-class palette into a decorative gradient. Esri’s ramp guidance emphasizes matching color strategy to the data theme and map background ([ArcGIS color-ramp guidance](https://developers.arcgis.com/javascript/latest/visualization/best-practices/choosing-a-color-ramp/)).
- **More polish can obscure analytical caveats.** Do not visually demote the preliminary screening notice, source/vintage, or authority labels; these already communicate important limits and provenance ([`MapPanel.tsx`, lines 504–506](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/MapPanel.tsx#L504-L506); [`Legend.tsx`, lines 88–120](https://github.com/AndrewBrown-USDA/fpac-soil-mcp/blob/8c90f0d6cf01d334fa089cafc2c371bda8e734ce/apps/agent-fpac-soil-openai-sdk/frontend/client/src/components/map/Legend.tsx#L88-L120)).
- **Map canvases can make controls hard to discover.** Avoid putting essential actions only in the map overlay or behind hover. Keep equivalent controls visible, keyboard-accessible, and operable without dragging ([WCAG 2.2 SC 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)).
- **Small targets and low contrast undermine compactness.** If the narrow panel motivates icon-only controls, provide labels/tooltips and ensure target sizing/spacing and focus state remain usable ([WCAG 2.2 SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)).
- **No visual inspection was performed.** The recommendations are grounded in source and design guidance, not screenshots or moderated usability findings; validate appearance and workflow effects before adopting them ([USWDS Design Principles](https://designsystem.digital.gov/design-principles/)).
